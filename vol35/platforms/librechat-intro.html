LibreChat

名前の手がかり: Libre フランス語・スペイン語で「自由な」 ＋ Chat おしゃべり・チャット

ChatGPT のような AI チャットの画面を、自分たちのサーバーで動かせるオープンソースのソフトウェア。複数の AI の提供元のモデルを、1つの画面から使える

たとえるなら（筆者の見立て）

各社の AI の「窓口」を社内に1つ用意し、誰がどの AI と道具を使えるかを会社が管理できるようにする仕組み

OpenAI・Anthropic・Google などの複数の提供元のモデルや、社内のモデルを、1つの画面から使えます。

2つの課題と、LibreChat の答え

課題と、その答えを対で並べています。

どのデータがどこへ送られたか分からず、費用もばらばらに発生する

シャドー IT（shadow IT）

社員が思い思いに外部のサービスを契約し、社内のデータを貼り付ける、ということが起きる。Thoughtworks は今回の版で、AI によって加速するシャドー IT を Caution の項目として取り上げ、LibreChat をその対策として位置づけている。

LibreChat の答え

自分たちのサーバーで動かし、つなぐ提供元とモデルは管理者が決める

つなぐ提供元とモデルは、管理者が librechat.yaml に書く。決めたモデルの設定（model specs）を並べて選ばせ、モデルを自由に選ぶ画面を出さないこともできる。残高の機能（既定では無効）を有効にすれば、利用者ごとのトークンの残高で費用を抑えられ、使った分の記録は自分たちのデータベースに残る。ただし、送った先の提供元がデータをどう扱うかは、それぞれの提供元との契約による（筆者の見立て）。「試してみる」の図で試せます。

禁止するのではなく、会社が認めたモデルと道具を、会社の認証と権限の下で使わせたい

AI を禁止すれば済むわけでもない。そこで、会社が認めたモデルと道具を、会社の認証と権限の下で、使いやすい画面から使わせる、という考え方が出てくる（筆者の見立て）。

LibreChat の答え

社内の認証でログインさせ、ロールごとに使う・作る・共有するを切り替える

社内の認証基盤（OAuth/OIDC・SAML・LDAP）でログインさせ、ロールごとに、エージェントや MCP を使う・作る・共有する権限を切り替えられる。MCP のサーバーは管理者が librechat.yaml で定義し、利用者が自分で足せるか（足せるのはリモートのサーバーだけ）もロールの権限で決める。ただし既定では、利用者は MCP のサーバーを使う・作ることができ、共有だけが許可制なので、絞るなら権限を変える。作ったエージェントは、利用者・グループ・ロールを選んで共有でき、エージェントのマーケットプレイスで探せる。「試してみる」の図で試せます。

試してみる: 社員の1つの依頼は、どこを通り、何が残るか

つなげるモデル

OpenAI・Azure OpenAI・Anthropic・Google・AWS Bedrock などに加え、Ollama（手元で LLM〈大規模言語モデル〉を動かす道具）や OpenRouter などにもつなげる。OpenAI 互換の API を持つものは、カスタムエンドポイントとして設定で足せる。

ログインと利用量

メールとパスワード、Google や GitHub などのアカウント、OAuth/OIDC、SAML、LDAP。メールとパスワード、または LDAP の利用者は2段階の認証も使える（SSO では認証基盤の側で行う）。利用者ごとのトークンの残高も設定できる。

設定の2つのファイル

.env には API キー・データベースの接続先・認証の秘密の値など。librechat.yaml には、つなぐモデルや MCP のサーバー・画面の設定など。

動かし方

Docker Compose が推奨。既定の構成では、本体のほか、MongoDB・Meilisearch（会話の検索）・RAG API・PostgreSQL と pgvector のデータベース（ファイルの検索用）を一緒に起動する。Kubernetes 向けの Helm のチャートもある。本体とは別に動かす管理画面（v0.8.5 以降）で、利用者・グループ・ロール・設定を管理できる。

トレードオフ

位置づけ: 社内の利用者と、外部・社内の AI モデルや道具の間に立つ、利用者向けの入口。モデルそのものを動かす基盤（KServe など）とは役割が違い、画面・認証・権限・道具の管理を担う（筆者の見立て）。

メリット

  • 提供元を選べる: 複数の提供元や社内のモデルを1つの画面で切り替えられ、特定の提供元に縛られにくい（縛られにくさは筆者の見立て）
  • 管理された形で配れる: 会社の認証基盤でログインさせ、ロールで権限を分け、利用量を残高で抑えられる
  • エンジニア以外も道具を作れる: Thoughtworks は、管理者が使える MCP のサーバーを決め、権限のある人がコードを書かずにエージェントを作って共有できる点を評価している

デメリット・注意点

  • 運用の責任を負う: データベースや検索などの部品を含めて、版上げ・バックアップ・監視を自分たちで行う（運用の負担は筆者の見立て）
  • 安全の設定に気を配る: コードを実行させる機能（Code Interpreter）には、管理者が別に立てるサンドボックスの部品が要る。仮想マシンや手元の PC を実行環境としてつなぐ場合、公式は、それを未知のコードを動かす機械と同じように隔離するよう求めている。画面を守る HTTP のヘッダーの一部（CSP）は既定で無効
  • 最初の管理者: 利用者のまとまり（テナント）が1つの構成では、最初に作られたアカウントが管理者になるため、導入の直後に自分で作るよう公式が勧めている
  • 版上げで互換性が変わることがある: 更新の前に、互換性を壊す変更を変更履歴で確かめるよう公式が勧めている

試すときに考える5つのこと

使うかどうか、どう入れるかを考えるための観点を、詳しい解説の第5節から並べました（筆者の整理）。

目的は何か？

社員に AI を安全に配ることが目的なら候補になる。開発者がコードの中から AI を呼ぶだけなら、画面の基盤は要らない（筆者の見立て）。

社内の認証基盤とつなげるか？

社内の認証基盤（OIDC・SAML・LDAP のどれで）とつなげるかを先に確かめる。

道具をどう管理するか？

どの MCP のサーバーを誰に使わせるか、エージェントの共有をどこまで許すかの決まりを作る（筆者の見立て）。

費用は？

LibreChat 自体は無料だが、モデルの利用料と、サーバー・運用の人手がかかる（筆者の見立て）。

運営体制は？

公式のドキュメントは、LibreChat が ClickHouse（データベースの会社）に加わったと告知している。Thoughtworks は、2025年11月の買収のあとも MIT ライセンスが保たれているとしている。今後の方針は見守る必要がある（筆者の見立て）。

シャドー IT

shadow ＝ 影 ／ IT ＝ Information Technology（情報技術）

会社の IT 部門が把握・管理していないところで、社員や部署が独自に使い始めたサービスや道具。

エージェント

agent ＝ 代理人

指示と道具を持たせ、複数の手順を自分で選んで仕事を進める AI のアシスタント。

MCP

MCP ＝ Model Context Protocol（model モデル ＋ context 文脈 ＋ protocol 通信の取り決め）

AI のアプリに外部の道具やデータをつなぐための共通の取り決め。

RAG

RAG ＝ Retrieval-Augmented Generation（retrieval 取り出すこと で augmented 補強した generation 生成）

質問に関係する文書を検索で取り出し、それを AI に渡して答えさせる方法。

埋め込み

embedding ＝ 埋め込むこと

文章の意味を数値の並び（ベクトル）に変えること。意味の近い文章を探すのに使う。

トークン

token ＝ しるし・代用の硬貨

AI のモデルが文章を処理するときの単位（単語や単語の一部）。利用料の計算にも使う。

LLM

LLM ＝ Large Language Model（大規模言語モデル）

大量の文章で学習し、文章を生成する AI モデル。

OAuth/OIDC

OAuth ＝ open 開かれた ＋ authorization 認可 ／ OIDC ＝ OpenID Connect

ほかのサービスのアカウントや社内の認証基盤を使ってログインさせるための、標準の仕組み。

SSO

SSO ＝ Single Sign-On（一度のサインオン〈ログイン〉）

1回のログインで、複数のサービスを使えるようにする仕組み。

SAML・LDAP

SAML ＝ Security Assertion Markup Language（安全のための表明を書く言語） ／ LDAP ＝ Lightweight Directory Access Protocol（軽量な名簿の参照の取り決め）

企業でよく使われる、ログインや利用者の情報を社内の認証基盤とつなぐための仕組み。

ロール

role ＝ 役割

「管理者」「一般利用者」のような役割。役割ごとに使える機能を決める。

Docker Compose

compose ＝ 組み立てる（Docker は製品名）

複数のコンテナの組み合わせを1つの設定ファイルに書き、まとめて起動する道具。

CSP

CSP ＝ Content Security Policy（content 中身 ＋ security 安全 ＋ policy 方針）

Web の画面で読み込んでよいスクリプトなどを制限し、攻撃を防ぐための HTTP のヘッダー。
