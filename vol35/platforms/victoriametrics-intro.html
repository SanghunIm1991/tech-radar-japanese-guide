VictoriaMetrics

名前の手がかり: Victoria ラテン語で「勝利」 ＋ Metrics 測った値

サーバーの「調子」を表す数値を、時刻つきで大量に貯めて、すぐ探せるデータベース

たとえるなら

体温や血圧を毎分記録し続ける、カルテの保管庫

ため込むだけでなく、「熱が上がったのはいつか」をすぐ探せることが大事です。この数値をメトリクス（CPU 使用率・1秒あたりのリクエスト数など）、時刻と数値が並んだデータを時系列データと呼びます。コミュニティ版は無料で使えるオープンソース（Apache License 2.0）で、監視の定番 Prometheus と同じ方法で読み書きできます。

監視が大きくなると起きる4つの課題と、VictoriaMetrics の答え

左が課題、右が答えです。答えはどれも開発元の説明・主張で、数値は開発元自身による比較です。

系列が爆発する

高カーディナリティ（high cardinality）

数値に付くラベル（どのサーバー・どの画面）の組み合わせごとに別々の系列になり、数百万にもなる。

少ないメモリで多くの系列を扱う

Prometheus など
VictoriaMetrics

メモリは最大で7分の1。比べる相手は Prometheus・Thanos・Cortex で、数百万の系列を扱う条件での比較。棒は、いちばん差が大きい場合です。

系列が入れ替わる

高チャーン（high churn）

Kubernetes の Pod のように入れ物が作り直されるたび、新しい系列が生まれては消える。

入れ替わりの激しい系列向けに最適化

開発元はそう説明しています。どう最適化しているかの中身は、元の解説でも確かめていません。

長く残すほど高い

長期保存（long-term storage）

数か月〜数年分を持つと、ディスクの容量と検索の速さが問題になる。

データを強く圧縮して、ディスクを減らす

Prometheus など
VictoriaMetrics

ディスクは最大で7分の1（比べる相手は同じ。棒は、いちばん差が大きい場合）。Prometheus の長期保存の保存先として使える。

1台では足りない

規模の拡大（scaling）

Prometheus の手元の保存領域は、1台のサーバーの能力と耐久性に限られる。

まず1台を強くし、超えたら台数を増やす

単一ノード版は CPU やメモリを増やして伸ばす（縦の拡張）。それを超えたら、クラスター版で部品ごとに台数を増やす（横の拡張。クラスター版でも各部品の縦の拡張はできる）。下の図で、自分の規模を当てはめて試せます。

「1台では足りない」への答え: 2つの形態

1,0001万10万100万1,000万1億

得るもの

  • 少ないメモリとディスク（上の棒。開発元自身による比較なので、自分たちのデータで確かめる）
  • Prometheus や Grafana の設定・画面をほぼそのまま生かせる
  • 規模に応じて単一ノード版とクラスター版を選べる

代わりに失うもの

  • 止まらないことを優先: 保管係の一部が止まると、検索結果が一部欠けることがある（エラーにする設定や複製で対処できる）
  • 保管係を増やしても、過去のデータは自動では移らない
  • 検索言語 MetricsQL は、PromQL とわずかに違う結果を返す計算がある
  • ダウンサンプリングなどは有料のエンタープライズ版だけ

THOUGHTWORKS の評価（要旨）

大規模な監視の仕組みを自分たちで運用する組織にとって、実運用に耐える段階に達したと、Thoughtworks は見ています。理由は、大量で系列の多いメトリクスに強いこと、規模に応じて2つの形態を選べること、Prometheus や OpenTelemetry と互換があることです。

用語（タップで開く）

青い字は元の語（英単語・略語・名前の元になった語）と、その意味です。覚えるための手がかりにしてください。

メトリクス・時系列データ

metrics ＝ metric（測った値）の複数形 ／ time series ＝ 時間＋ひと続きの並び

システムの状態を表す数値と、それを時刻の順に並べたデータ。

Prometheus

Prometheus ＝ ギリシャ神話で、人間に火を与えたティーターン（巨人族の神）の名前

監視の分野で広く使われているオープンソースのツール。監視対象から数値を定期的に集めて保存し、検索やアラートに使う。

ラベル・カーディナリティ

label ＝ 荷札・名札 ／ cardinality ＝ 数学で、集合に含まれる要素の数

ラベルは数値に付ける目印。その値の組み合わせの数がカーディナリティで、多いほど保存の負担が大きい。

チャーン

churn ＝ かき混ぜる（転じて、入れ替わり）

系列が次々に生まれては消える入れ替わりのこと。高チャーンは、入れ替わりが激しい状態。

Kubernetes・Pod

Kubernetes ＝ ギリシャ語で「操舵手（船のかじを取る人）」。K8s は K と s の間の8文字を数字にした略 ／ pod ＝ 豆のさや、クジラなどの群れ

Kubernetes は多数のコンテナをまとめて配置・管理する仕組み。Pod はその中でアプリケーションを動かす最小の単位で、作り直されると別の名前になる。

remote write

remote ＝ 離れた ／ write ＝ 書き込む

Prometheus が集めたデータを、外部の保存先へ送る仕組み。VictoriaMetrics を長期の保存先にするときに使う。

PromQL / MetricsQL

PromQL ＝ Prometheus Query Language（query は「問い合わせ」）の略

PromQL は Prometheus の検索言語。MetricsQL は VictoriaMetrics の検索言語で、PromQL にならって作られ、PromQL の書き方を受け付けたうえで機能を足したもの。

ダウンサンプリング

downsampling ＝ down（下げる）＋ sampling（一定の間隔で値を取ること）

古いデータの粒度を「1分ごと」から「1時間ごと」のように粗くして、容量を節約し検索を速くすること。

冗長化・可用性

redundancy ＝ 余分・重複 ／ availability ＝ 使えること

冗長化は、予備を用意して一部が壊れても止まらないようにすること。可用性は、止まらずに使える度合い。
