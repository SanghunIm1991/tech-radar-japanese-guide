OpenAI Codex

名前の手がかり: OpenAI 会社名（Open 開かれた ＋ AI 人工知能）＋ Codex ラテン語で、紙を綴じた冊子の形の本・写本

OpenAI が提供するコーディングエージェント。コードを読み、書き換え、コマンドを実行して作業を進める。どこまで動いてよいかを、サンドボックスと承認の方針で囲う

たとえるなら

「この不具合を直して」と頼むと、自分でファイルを開き、直し、テストを走らせて報告してくれる同僚

ただし、どこまで勝手に動いてよいかは、こちらが決めて囲っておく必要があります。Codex では、囲いがサンドボックス、門の呼び鈴が承認の方針にあたります。

2つの課題と、Codex の答え

課題と、その答えを対で並べています。

コードを貼り付け、試し、エラーを貼り戻す往復を、人が担う

チャット型の AI の使い方

質問してコード片をもらう使い方では、試した結果を AI に伝え直すのは人の仕事になる。

Codex の答え

リポジトリを自分で読み書きし、コマンドで確かめながら進める

ファイルを読んで書き換え、テストなどのコマンドを実行して結果を確かめる。クラウドでは作業ごとに分けた環境で複数の作業を並べて進め、変更をプルリクエストにできる。codex exec なら、人が端末の前にいなくても、スクリプトや CI から任せられる。使う場所を見る。

AI にコマンドを実行させると、事故の危険が生まれる

コマンドを実行させる使い方

ファイルを消す、秘密の情報を外へ送る、といった事故が起きうる。

Codex の答え

囲い（サンドボックス）と呼び鈴（承認の方針）を組み合わせる

モードで書き込める範囲を決め、承認の方針で囲いの外に出る操作の前に人に聞くかを決める。既定ではネットワークに出られない状態で動く（ただし、承認したコマンドや、許可したネットワーク・MCP のサーバーは囲いの外に出られる）。囲いを外す指定もあるので、どの設定で使うかは利用者が決める。「試してみる」の図で試せます。

使う場所

CLI端末で codex と打って対話する。本体は Rust で書かれた Apache-2.0 のオープンソース
エディタの拡張・デスクトップアプリ画面の上で同じエージェントを使う
クラウド作業ごとに分けた環境で動かし、変更を確かめてプルリクエストにできる。ChatGPT の Web やモバイルアプリからも使える
codex exec・GitHub Actionsスクリプトや CI から呼ぶ。公式のアクション openai/codex-action もある

作業の前に、AI 向けの指示書 AGENTS.md を読みます（~/.codex のものと、リポジトリの根元から今のフォルダまでのものを順につなげ、今のフォルダに近いものが後ろに来る）。外部の道具やデータは MCP でつなげます。

試してみる: 囲いと呼び鈴の設定で、何が起きるか

課題2（AI にコマンドを実行させる事故の危険）への答えを、設定を変えて確かめる図です。エージェントが作業中にしようとする5つの操作が、設定によって「そのまま進む」「人に聞く」「止まる」のどれになるかを示します。詳しい解説に書いた範囲を、筆者が整理して簡略化したものです（実際の動きは OS や設定の細部で変わりうるので、公式の文書で確かめてください）。

サンドボックスのモード（囲いの広さ）
承認の方針（囲いの外に出る前に聞くか）
ネットワーク（workspace-write のときだけ選べる）
そのまま進む人に聞く（承認）止まる（その操作は囲いに阻まれる）

得るもの

  • 作業の自動化: 調査・修正・テストの往復を任せられる。クラウドでは複数の作業を並べて進められる
  • 企業での管理のしやすさ: OS の仕組みによる囲いと、段階的な承認の方針がある。設定は個人・プロジェクトのほか、組織のワークスペースから配られる既定値やマシン全体の設定からも読み込まれ、管理された PC では組織が requirements.toml で縛れる
  • 組み込みやすさ: codex exec、GitHub のアクション、TypeScript と Python の SDK で、ほかの仕組みから呼べる

代わりに失うもの・注意点

  • 出力の質は保証されない: 動くが古い書き方のコードを出すことがあり、自動テストと人のレビューが欠かせない（Thoughtworks の前の版〈2026年4月〉の注意）
  • 権限の設計が要る: 承認とサンドボックスを両方外す指定は、公式が「推奨しない」としている。danger-full-access も、公式は慎重に使うよう求めている
  • コードが外へ出る: モデルに渡す指示には手元のコードが含まれ、提供元のサービスへ送られる（筆者の見立て）。公式も、監視のログに指示を残さないよう、log_user_prompt = false のままにすることを勧めている
  • 提供元への依存: 本体はオープンソースだが、開発は OpenAI が主導し、コミュニティで運営されているわけではない（Thoughtworks の指摘）

導入するときに決める5つのこと

始める前に決めておくことを、詳しい解説の第5節から5つにまとめました（筆者の整理）。

どの契約で使うか？

ChatGPT のプランでサインインすると、プランの利用枠の中で使える。API キーなら API の通常の料金。クラウドの機能には ChatGPT でのサインインが要る。

社外に出してよいコードか？

先に決める。学習への利用や保存期間は、契約の種類ごとの規約で確かめる（筆者の見立て）。

権限の既定値をどうするか？

チームで使うなら、モードと承認の方針、ネットワークの可否を設定で決めておく。CI では、codex exec は既定で read-only で動く。

どの OS で使うか？

macOS・Linux に加え、Windows でも PowerShell のまま専用のサンドボックスで動かせる。Windows 11 が推奨で、Windows 10 は最善努力の扱い。

AI の変更を誰が確かめるか？

レビューの体制を決める。テストが薄いリポジトリでは、効果より危険が勝ちやすい（筆者の見立て）。

コーディングエージェント

coding ＝ プログラムを書くこと ／ agent ＝ 代わりに行動する者・代理人

指示を受けて、コードを読み、書き換え、コマンドを実行するといった複数の手順を自分で選んで進める AI の道具。

サンドボックス

sandbox ＝ 子どもが遊ぶ砂場

プログラムが触れられるファイルやネットワークを、OS の仕組みで限られた範囲に閉じ込める仕組み。

承認の方針

approval ＝ 承認 ／ policy ＝ 方針（設定の名前は approval_policy）

AI が危ないかもしれない操作をする前に、人に確認を求めるかどうかの決まり。

AGENTS.md

agents ＝ エージェントたち ＋ .md（Markdown のファイルの拡張子）

リポジトリに置く（全体用は ~/.codex に置く）、AI のエージェント向けの指示書。作業の決まりや、テストの走らせ方などを書く。

MCP

MCP ＝ Model Context Protocol（モデルにコンテキストを渡すための約束事）

AI のアプリに外部の道具やデータをつなぐための共通の取り決め。

CLI

CLI ＝ Command Line Interface（コマンドの行で操作する接点）

文字のコマンドを打って操作する道具。

CI

CI ＝ Continuous Integration（継続的な統合）

変更のたびに、自動でビルドやテストを行う仕組み。

SDK

SDK ＝ Software Development Kit（ソフトウェアの開発の道具一式）

ほかのプログラムからその機能を呼び出すための部品一式。

プルリクエスト

pull ＝ 引く ／ request ＝ 依頼（自分の変更を引き込んでもらう依頼）

変更を本流に取り込む前に、レビューを依頼する GitHub などの仕組み。

API キー

API ＝ Application Programming Interface（アプリをプログラムから使うための接点） ／ key ＝ 鍵

プログラムからサービスを使うときに、利用者を識別するための秘密の文字列。使った分だけ課金されることが多い。
