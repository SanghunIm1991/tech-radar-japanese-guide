OpenCode

名前の手がかり: Open 開かれた・公開された ＋ Code プログラムのコード

オープンソースのコーディングエージェント。いちばんの特徴は、特定の AI モデルの提供元に縛られず、クラウドのモデルにも、社内や手元の PC で動かすモデルにもつなげること

たとえるなら（筆者の見立て）

エンジン（モデル）を積み替えられる車

車体にあたるのが、コードを読み、書き換え、コマンドを実行して作業を進めるコーディングエージェントです。エンジンにあたる AI のモデルを、クラウドの提供元のものにも、社内や手元の PC で動かすものにも替えられます。

3つの課題と、OpenCode の答え

課題と、その答えを対で並べています。課題の多くは筆者の見立てです。

モデル・費用・データの送り先が、エージェントを出す会社に縛られる

提供元への縛り

コーディングエージェントは、モデルを作る会社が自社のモデル向けに出しているものが多い（筆者の見立て）。

OpenCode の答え

モデルの提供元を選べる。エージェント自体も公開されている

models.dev のカタログにある多くの提供元から選び、/connect と /models で切り替えられる。OpenAI 互換の API を持つ独自の提供元も足せる。エージェントは MIT ライセンスで公開されていて、中身を読んで変えられる。「試してみる」の図で試せます。

費用を抑えたい、コードを社外に出したくない、切り離した環境で使いたい

企業の要望

インターネットから切り離された環境（エアギャップ）で使いたい、といった要望もある（筆者の見立て）。

OpenCode の答え

社内や手元の PC で動かすモデルにもつなげる

Ollama・LM Studio・vLLM にもつなげる。費用や性能に合わせてモデルを選び、手元のモデルを使えば、コードを社外に出さない構成を組める（構成の判断は筆者の見立て）。ただし、切り離した環境で動くことを、確認した範囲の公式のドキュメントは明記していないので、その用途では自分たちで確かめる（筆者の見立て）。Thoughtworks は2026年4月の版で、制限のある環境やエアギャップの環境に向くと評価していた。「試してみる」の図で試せます。

オープンウェイトモデルを、自前で動かす選択肢が現実的になった

オープンウェイトモデル（open-weight model）

学習済みの重みが公開されたモデルの性能が上がってきた（筆者の見立て）。

OpenCode の答え

自前で動かすオープンウェイトモデルも、見つけて選べる・設定で足せる

自前で動かすオープンウェイトモデルも、Ollama などで決まったアドレスで動かしていれば自動で見つけて選べ、OpenAI 互換の API で公開したモデルも設定で足せる。Thoughtworks は今回の版で、OpenCode がオープンウェイトのモデルや自前で動かすモデル、手元で動かすコーディング向けのモデルと組み合わせる用途で広く使われるようになったと見ている。「試してみる」の図で試せます。

試してみる: どのモデルにつなぐと、コードはどこへ行くか

課題1〜3への答えを確かめる図です。つなぐモデルを選ぶと、エージェントがモデルに渡す指示（手元のコードを含む。筆者の整理）の送り先と、選ぶときの注意が変わります。送り先の分け方は、詳しい解説の範囲を筆者が整理したものです。

試してみる: 権限の既定値は「ゆるい」

3つの課題への答えではなく、使うときの注意点（安全の設計）を確かめる図です。AI が行う操作ごとに、allow（許可）・ask（毎回確認）・deny（拒否）を決めます。既定は基本「すべて許可」で、確認を求めるのは .env の読み取りなどに限られます。主な操作で、既定とチームで締めた例を比べてください（締めた例は、詳しい解説の第5節の例による）。

allow（許可）ask（毎回確認）

組み込みのエージェント

build既定。ファイルの編集もコマンドの実行も行う
plan調べて計画を立てる。通常のプロジェクトのファイルは編集しない
general複数の手順にわたる調査などを任せるサブエージェント
exploreコードや Web を探して読むだけのサブエージェント

自分のエージェントも Markdown のファイルで定義できます。指示書の AGENTS.md を読み、MCP・カスタムコマンド・プラグインで広げられます。opencode run・opencode serve・SDK で、画面なしでほかの仕組みから呼べます。公式のドキュメントは確認日の時点で「V2」が中心で、V1 から設定の名前がいくつか変わっています。

得るもの

  • モデルを選べる: 費用・性能・データの置き場所に合わせてモデルを替えられる
  • 中身を読めて、変えられる: MIT ライセンスで、エージェント・コマンド・プラグインを自分たちで足せる
  • 組み込みやすさ: opencode run・サーバー・SDK で、ほかの仕組みから呼べる。社内向けの AI の開発基盤の「土台」にもなる（筆者の見立て）

代わりに失うもの・注意点

  • 安全の設計は自分たちの仕事: 既定は「ほぼ許可」で、OS による囲いの記述も見当たらない。権限の規則を締めるか、コンテナなどの外側の囲いと組み合わせる（筆者の見立て）
  • 品質はモデル次第: 小さな手元のモデルでは、期待した質に届かないことがある（筆者の見立て）
  • 共有や共同作業の機能: Thoughtworks は、作業の記録の共有や共同作業の機能が、ほかのエージェントより遅れていると指摘している
  • 変化が速い: V1 から V2 で設定の名前が変わった。チームでは版を固定し、誰が移行を確かめるかを決めておく（筆者の見立て）

導入するときに決める4つのこと

始める前に決めておくことを、詳しい解説の第5節から4つにまとめました（筆者の整理）。

費用をどこに払うか？

OpenCode 自体はオープンソースだが、モデルの利用料は提供元ごとにかかる。開発元は、オープンウェイトのモデルを中心に打ち出した、利用量の上限つきの月額の固定料金のプラン「OpenCode Go」も提供している。Thoughtworks は2026年4月の版で、提供元のサブスクリプションや API を使うときに、ライセンスと利用規約を確かめるよう注意していた。

コードをどこに置くか？

社外に出せないコードなら、社内や手元のモデルを選ぶ（筆者の見立て）。

権限の規則をどう配るか？

shell や edit、作業フォルダの外への操作（external_directory）を ask にするといった規則を決めて配る。強制したい規則は、管理者が policies に書く。

どの OS にどう入れるか？

スクリプトや npm・Homebrew・mise などで入れられる。Windows では、Windows のパッケージ管理の道具（Scoop・WinGet など）には対応しておらず、端末で使う版は配布の zip を使う。デスクトップアプリには Windows 版のインストーラーがある。

コーディングエージェント

coding ＝ プログラムを書くこと ／ agent ＝ 代わりに行動する者・代理人

指示を受けて、コードを読み、書き換え、コマンドを実行するといった複数の手順を自分で選んで進める AI の道具。

TUI

TUI ＝ Text-based User Interface（Terminal User Interface とも。文字で組んだ、利用者との接点）

端末の中に、文字で組んだ画面を出して操作する形。

オープンウェイトモデル

open ＝ 公開された ／ weight ＝ 重み ／ model ＝ 模型・モデル

学習済みの重み（モデルの中身の数値）が公開されていて、自分のサーバーや PC で動かせる AI モデル。

エアギャップ

air ＝ 空気 ／ gap ＝ すき間（間に空気しか無い、つまりつながっていない）

機密を守るため、インターネットなどの外のネットワークから物理的に切り離した環境。

サブエージェント

sub ＝ 下の・副の ／ agent ＝ 代理人

親のエージェントから仕事を任される子のエージェント。調査などを分けて行い、結果だけを親に返す。

サンドボックス

sandbox ＝ 子どもが遊ぶ砂場

プログラムが触れられるファイルやネットワークを、OS の仕組みで限られた範囲に閉じ込める仕組み。

AGENTS.md

agents ＝ エージェントたち ＋ .md（Markdown のファイルの拡張子）

リポジトリなどに置く、AI のエージェント向けの指示書。作業の決まりや、テストの走らせ方などを書く。

MCP

MCP ＝ Model Context Protocol（モデルにコンテキストを渡すための約束事）

AI のアプリに外部の道具やデータをつなぐための共通の取り決め。

SDK

SDK ＝ Software Development Kit（ソフトウェアの開発の道具一式）

ほかのプログラムからその機能を呼び出すための部品一式。

API

API ＝ Application Programming Interface（アプリをプログラムから使うための接点）

ほかのプログラムからサービスの機能を呼び出すための決まった呼び方。「OpenAI 互換の API」は、OpenAI の API と同じ形で呼べるもの。
