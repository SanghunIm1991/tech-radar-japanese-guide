Post-quantum cryptography

名前の手がかり: Post 〜の後 ＋ quantum 量子 ＋ cryptography 暗号の技術。量子コンピュータの時代の後も使える暗号

将来の量子コンピュータでも破られないように設計された新しい暗号（PQC）と、そこへ計画的に切り替えていく取り組み

PQC は「量子暗号」とは別物

PQC は、今のコンピュータで動く普通の数学の暗号で、従来のコンピュータでも量子コンピュータでも解きにくい問題を土台にしています。量子の物理現象を使う「量子暗号」とは別のものです（NIST）。

インターネットの安全は、公開鍵暗号（RSA や楕円曲線暗号など）に支えられています。通信を暗号化するときの鍵の受け渡しや、文書やソフトウェアが本物だと示す電子署名に使われています。その安全は「大きな数の素因数分解」のような、今のコンピュータでは現実的な時間で解けない問題に頼っています。

3つの課題と、PQC の答え

課題と、その答えを対で並べています。

量子コンピュータが現れると、今の暗号の多くが破られる

公開鍵暗号（public key cryptography）

十分に強力な量子コンピュータは、公開鍵暗号が頼る数学の問題を桁違いに速く解けると考えられている。そうなれば、今広く使われている暗号の多くが破られうる（NIST）。

量子コンピュータでも解きにくい問題を土台にした方式に置き換える

格子やハッシュ関数などを土台にした新しい方式にする。NIST は2024年8月に最初の3つの標準を公開した（下の3枚のカード）。

今盗んで、あとで解読される

harvest now, decrypt later

攻撃者が暗号化された通信を今のうちに記録しておき、量子コンピュータができたときに解読する。何年も価値を持つ秘密（医療・金融・国家の情報など）が危ない（NIST）。

いちばん急ぐのは、鍵の受け渡し（鍵交換）

今の通信の鍵交換を PQC（移行の途中では従来の方式と組み合わせたハイブリッド方式）にすれば、切り替えた後に記録された通信は、あとで解読されにくくなる。切り替える前の記録は守れないので、早いほど守れる範囲が広い（筆者の見立て。相手も PQC に対応している場合）。Thoughtworks は鍵交換の移行が最も急ぐとしている。下の図で試せます。

切り替えに10〜20年かかる

移行（migration）

暗号の標準ができてからシステムに行き渡るまで、過去の例で10〜20年かかった。量子コンピュータが現れる時期の専門家の見積もりは、数年後から数十年後まで幅がある（NIST）。

期限から逆算して、計画的に移る

まず暗号の使い道を棚卸しし、守る期間の長いデータから移す。方式を差し替えやすい設計（クリプトアジリティ）にしておく（下の期限の年表）。

NIST の最初の3つの標準（2024年8月）

FIPS 203ML-KEM鍵カプセル化（通信の両側で、共通の秘密の鍵を安全に共有する）土台: 格子
FIPS 204ML-DSA電子署名土台: 格子
FIPS 205SLH-DSA電子署名土台: ハッシュ関数

このほか、鍵カプセル化の2つめの方式として HQC が選ばれ、標準化が進んでいます。

試してみる: 切り替えが遅いほど、あとで解読されうる記録が増える

攻撃者が、2026年から2035年まで毎年の通信を記録し続けているとします（封筒）。鍵交換を PQC（ハイブリッド方式）に切り替える年をスライダーで選び、「量子コンピュータが現れたとする」を押してください。年の並びと記録は、説明のための例です。量子コンピュータが現れる年は決めていません。

2026年右端は「切り替えない」
従来の暗号だけで守った記録PQC（ハイブリッド）で守った記録解読されうる記録

この図はスクリプトで動きます。要点: 切り替える前に記録された通信は、あとから PQC にしても守れません（筆者の見立て）。切り替えが早いほど、量子コンピュータが現れたときに解読されうる記録は少なくなります（相手も PQC に対応している場合）。

ハイブリッド方式: 従来の暗号と PQC を組み合わせる

新しい暗号はまだ実績が浅いため（筆者の見立て）、移行の途中では、従来の鍵交換と PQC を組み合わせる方式がよく使われます。どちらか一方が安全である限り、全体の安全が保たれるという考え方です。TLS 1.3 では、X25519 などの従来の鍵交換と ML-KEM を組み合わせる方式が IETF の規格（RFC 10024）になりました。主要なブラウザのいくつかは、すでに対応しています（NCSC のページの公開時点〈2025年3月〉の記述）。

移行の期限の目安

2028現状を把握し、移行の計画を立てるNCSC の目安
2031優先度の高い移行を終えるNCSC の目安
2035すべての移行を終える（NCSC の目安）量子コンピュータに弱い方式を標準から外す。危険の大きいシステムはもっと早く移す（NIST）

Thoughtworks は、各国の政府が2030〜2035年の移行を目標にしていることを挙げています。

得るもの

  • 量子コンピュータが現れても破られにくいと考えられる暗号
  • 鍵交換を早く移すほど、切り替えた後に記録される通信が将来解読される危険を減らせる（筆者の見立て。相手も PQC に対応している場合）
  • 移行の途中も、ハイブリッド方式なら、従来の暗号と PQC のどちらか一方が安全である限り、全体の安全が保たれる

代わりに失うもの・難しさ

従来（X25519）32バイト
ハイブリッド 約1.2KB

TLS の接続の最初に送る鍵のデータの大きさ（IETF の規格による）。

  • データが大きくなる: PQC の鍵や暗号文は、従来より大きくなりがち（上の棒）
  • 古い機器・作り直せない機器: 性能が低い、更新できない IoT 機器などは移行が難しい（NCSC）
  • 相互運用: 移行の期間中は新旧両方に対応する。Web の証明書の仕組みと産業用の制御システムは特に難しい（NCSC）
  • 気づかない後退: 相手が対応していないと、黙って従来の暗号に戻る（フォールバックする）ことがある。実際に PQC が使われているかを確かめる（NCSC）

PQC に取り組むときに決める5つのこと

Thoughtworks はこの手法を Adopt に置き、新しいシステムでは必須にし、既存のシステムでは移行の計画を前倒しするよう勧めています。次の5つは、そのときに考えることです。

新しいシステムでは？

最初から、量子コンピュータに耐える暗号を必須にする（Thoughtworks の勧め）。

どこで何を使っているか？

どのシステムが、どこで、どんな暗号を使っているかを棚卸しする。扱うデータが何年守られる必要があるかも確かめる（NCSC、NIST）。

どこから移すか？

長く価値を持つデータを扱うサービスから。急ぐのは鍵交換（Thoughtworks も同じ見方）。

使っている道具は対応しているか？

言語・フレームワーク・ライブラリの最新版には対応が入りつつある。更新や設定の変更が要ることがある（Thoughtworks）。暗号は自分で実装しない（NCSC）。

取引先はどうか？

使っている製品やクラウドの事業者に、PQC への対応の計画を確かめ（NCSC）、調達の要件に入れる（CISA のページに載った G7 の呼びかけも優先事項に挙げている）。

実現するための道具の例

推奨でも網羅でもない例です（2026-11-15 の時点）。暗号は自分で実装せず、信頼できるライブラリやサービスを使います。

OpenSSLOSS

広く使われる暗号と TLS のライブラリ。3.5.0（2025年4月）から ML-KEM・ML-DSA・SLH-DSA に対応し、TLS の既定でハイブリッド方式を優先し、X25519MLKEM768 の鍵を最初から送る。

Go の crypto/mlkemOSS（BSD-3-Clause。Go の標準ライブラリ）

ML-KEM（768 と 1024）の鍵カプセル化。多くの用途では ML-KEM-768 を勧めている。

liboqs（Open Quantum Safe）OSS（MIT）

PQC の方式を多数そろえた C のライブラリ。研究と試作のためのもので、本番環境や機微なデータの保護に使うことは勧めていない。

AWS KMS の耐量子の鍵商用のクラウドのサービス

鍵の管理のサービスで、ML-DSA（電子署名）と ML-KEM（鍵の確立）の鍵を作って使える。

量子コンピュータ

quantum ＝ 量子（もとはラテン語の「どれだけの量」） ／ computer ＝ 計算するもの

量子力学の性質を使って計算するコンピュータ。特定の種類の問題を、今のコンピュータより桁違いに速く解けると考えられている。

公開鍵暗号

public key ＝ 公開の鍵 ／ cryptography ＝ 暗号の技術

公開してよい鍵と秘密の鍵の組を使う暗号。鍵の受け渡しや電子署名に使われる。RSA や楕円曲線暗号が代表例。

電子署名

digital signature ＝ 電子の署名

データが本人によって作られ、改ざんされていないことを、暗号の技術で証明する仕組み。

鍵交換・鍵カプセル化

key exchange ＝ 鍵の交換 ／ KEM ＝ Key Encapsulation Mechanism（鍵をカプセルに包む仕組み）

通信する両者が、盗み見られても安全な方法で、共通の秘密の鍵を共有する仕組み。鍵カプセル化はその方式の一つ。

格子・ハッシュ関数

lattice ＝ 格子 ／ hash ＝ 細かく刻む ／ function ＝ 関数

PQC の土台になる数学。格子は多次元の空間に規則正しく並んだ点の集まりで、PQC はそれにかかわる解くのが難しい問題を使う。ハッシュ関数はデータから固定長の要約値を作る関数。

NIST・FIPS

NIST ＝ National Institute of Standards and Technology ／ FIPS ＝ Federal Information Processing Standards（連邦の情報処理の標準）

NIST は米国の国立標準技術研究所。FIPS は NIST が定める米国政府向けの情報処理の標準で、PQC の標準もこれとして公開された。

NCSC・CISA

NCSC ＝ National Cyber Security Centre ／ CISA ＝ Cybersecurity and Infrastructure Security Agency

NCSC は英国の、CISA は米国の、サイバーセキュリティを担う政府機関。

TLS

TLS ＝ Transport Layer Security（通信を運ぶ層の安全）

Web サイトとの通信などを暗号化する規格。URL が https で始まる通信で使われる。

IETF・RFC

IETF ＝ Internet Engineering Task Force ／ RFC ＝ Request for Comments（意見を求める文書）

IETF はインターネットの技術の標準を作る団体で、RFC はその文書。

ハイブリッド方式

hybrid ＝ 混ざったもの

従来の暗号と PQC を組み合わせて使う方式。どちらかが破られても、もう一方で安全を保つ。

クリプトアジリティ

crypto ＝ 暗号 ／ agility ＝ 身軽さ

暗号の方式を、システムを大きく作り直さずに差し替えられるようにしておく設計。

IoT

IoT ＝ Internet of Things（モノのインターネット）

インターネットにつながる機器（センサーや工場の機械など）。

フォールバック

fall back ＝ 後ろへ下がる

新しい方式が使えないときに、黙って古い方式に戻ってしまうこと。
