## 1. 一言でいうと

Small language models（SLM、小型言語モデル）は、ChatGPT などの背後にある大規模言語モデル（LLM）より**パラメータ（学習で決まる数値）の数がずっと少ない**言語モデルです。ここで取り上げる手法は、何でも最大のモデルに任せるのをやめ、要約・情報の抜き出し・問い合わせの振り分けのような**狭く、回数の多い仕事**には小型のモデルを選ぶ、というものです。

小型といっても数億〜数十億のパラメータがあり、パラメータ数を公表しないものも多い最大級のモデル（数千億〜兆の規模と推測されることが多い）と比べて「小さい」という意味です（筆者の見立て）。たとえるなら、どんな荷物にも大型トラックを出すのをやめ、近所の配達には軽自動車を使うようなものです。

## 2. 解決する課題（なぜ生まれたか）

大きなモデルは何でもそこそこできる一方で、1回の呼び出しの料金・応答の待ち時間・動かすための GPU（画像処理用に生まれ、AI の計算にも使われる演算装置）の費用が大きくなります。エージェントのように1つの作業でモデルを何十回も呼ぶ使い方が広がると、この費用が積み上がります（筆者の見立て）。

一方で、仕事の多くは「この問い合わせはどの窓口向けか」「この文書から日付と金額を抜き出す」のように、型の決まった狭いものです。こうした仕事に最大のモデルを使うのは過剰で、小さなモデルで十分なことがあります。さらに、小さなモデルは手元のパソコンやスマートフォン、工場の機器など（エッジ）で動かせるので、データを外に出さずに済み、通信が無くても使えます（筆者の見立て。費用が上がるなかで、仕事に合ったモデルを選ぶ動きは [Radar のページ](https://www.thoughtworks.com/en-us/radar/techniques/small-language-models)も挙げています。第7節）。

## 3. 仕組みの概要

**小さくても使えるようにする主な技術**

- **蒸留（distillation）**: 大きなモデル（先生）の出力を手本にして、小さなモデル（生徒）を学習させる方法です。正解だけでなく、先生が各選択肢にどれくらいの確からしさを付けたかまでまねることで、小さなモデルに知識を移します（[Hinton ら: Distilling the Knowledge in a Neural Network（arXiv:1503.02531）](https://arxiv.org/abs/1503.02531)）
- **量子化（quantization）**: モデルの数値を、32ビットや16ビットの浮動小数点から、8ビットの整数などの粗い形に置き換えます。計算が速くなり、消費電力が下がり、ノートパソコンやスマートフォンでも動かしやすくなる一方、精度が少し落ちることがあります。学習済みのモデルにあとからかける方法（PTQ、学習後の量子化）と、学習の段階で量子化を織り込む方法（QAT、量子化を意識した学習）があり、後者は性能を保ちやすいが手間と費用がかかります（[IBM: What is Quantization?](https://www.ibm.com/think/topics/quantization)）
- **質の高い学習データ**: 量より質を重んじたデータで学習させます。たとえば Phi-4-mini は、教科書のような合成データを学習に使ったとしています（[Hugging Face: Phi-4-mini-instruct](https://huggingface.co/microsoft/Phi-4-mini-instruct)）

**モデルの例**（数値は各モデルカードの記載。確認日の時点）

| モデル | パラメータ数 | 文脈の長さ | ライセンス | モデルカードに書かれた特徴 |
|---|---|---|---|---|
| [Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B) | 約6億 | 32,768 トークン | Apache 2.0 | 考える（推論する）モードと、考えないモードを切り替えられる。手元で動かす道具（llama.cpp など）を案内 |
| [Gemma 3 270M](https://huggingface.co/google/gemma-3-270m) | 2億7千万 | 32K トークン | Gemma の利用規約 | 要約・対話などの文章の生成。複雑な仕事や事実の正確さには限界があると明記 |
| [Phi-4-mini-instruct](https://huggingface.co/microsoft/Phi-4-mini-instruct) | 38億 | 128K トークン | MIT | 計算資源の限られた環境や、応答の速さが大事な場面を想定。関数の呼び出しに対応 |
| [Ministral 3 3B](https://huggingface.co/mistralai/Ministral-3-3B-Instruct-2512) | 約34億＋画像用の約4億 | 256K トークン | Apache 2.0 | エッジでの利用を想定。8ビットの浮動小数点（FP8）の重みで、8GB の GPU のメモリに収まるとする |

トークンは、LLM が文章を数える単位です。文脈の長さは、一度に読める文章の量の上限です。

**使い方の例**（筆者の整理）

1. 入口の小さなモデルで、問い合わせの種類を分類する（意図の分類）
2. 型の決まった仕事（抜き出し・要約・分類）は、小さなモデルがそのまま処理する
3. 複雑な推論が要るものだけを大きなモデルに回す

## 4. アーキテクチャ上の位置づけとトレードオフ

**位置づけ**: AI を使うシステムの「どの仕事にどのモデルを割り当てるか」の設計です。データベースで、すべてを高価な製品に載せず、用途ごとに向いたものを選ぶのと同じ考え方を、モデルの選び方に当てはめたものです（筆者の見立て）。

**得られるもの**

- **費用と速さ**: パラメータが少ないほど、1回の推論（モデルに答えを出させる計算）の計算量が減り、料金と待ち時間が下がる（筆者の見立て）
- **データを外に出さない**: 手元や自社の機器で動かせば、外部の API にデータを送らずに済む（筆者の見立て）
- **専用に仕立てやすい**: 小さいので、自社のデータで追加の学習（ファインチューニング）をする費用も小さい。Phi-4-mini のカードは追加の学習の手順の例を載せている（[Hugging Face: Phi-4-mini-instruct](https://huggingface.co/microsoft/Phi-4-mini-instruct)）

**代わりに失うもの・注意点**

- **知識と推論の限界**: 小さなモデルは覚えている知識が少なく、事実を誤りやすい。Phi-4-mini のカードは、事実の誤りという弱点は検索エンジンで補えば解消できる可能性があると書き（RAG の考え方）、関数の呼び出しで関数名や URL をでっち上げることがあるとも書いている（[Hugging Face: Phi-4-mini-instruct](https://huggingface.co/microsoft/Phi-4-mini-instruct)）
- **エージェントには向かないことがある**: 何段階もの推論や、確実なツールの呼び出しが要る仕事では、大きなモデルのほうが安全（筆者の見立て。[Radar のページ](https://www.thoughtworks.com/en-us/radar/techniques/small-language-models)も同様の注意を挙げている）
- **運用の手間**: 自前で動かすなら、GPU の確保・モデルの更新・監視を自分たちで担う（筆者の見立て）
- **振り分けの誤り**: 小さなモデルに回した仕事が、実は難しかったときに質が落ちる。振り分けの基準と、品質の測り方が要る（筆者の見立て）

## 5. 採用を判断するときの観点

- **仕事の性質**: 入力と出力の型が決まっているか、回数が多いか。どちらも当てはまるなら候補になる（筆者の見立て）
- **評価の用意**: 自分たちの実際のデータで、大きなモデルと小さなモデルの正答率を比べる評価の課題を用意する。公開のベンチマークの点数だけで決めない（筆者の見立て）
- **動かす場所**: API で使うか、自社のサーバーか、端末の上か。端末なら、量子化した版がその機器のメモリに収まるか（筆者の見立て）
- **ライセンス**: Apache 2.0・MIT のような一般的なものか、独自の利用規約か。商用の条件を確かめる（各モデルカード）
- **費用の比較**: 1件あたりの料金だけでなく、自前で動かす場合の GPU と人手の費用も含めて比べる（筆者の見立て）
- **言語**: 学習データが主に英語のモデルでは、日本語の性能が落ちることがある。日本語で試す（Phi-4-mini のカードは、英語以外の言語で性能の差があると書いている）

## 6. 関連技術・代替技術

- **Model distillation**: [Radar の Small language models のページ](https://www.thoughtworks.com/en-us/radar/techniques/small-language-models)の関連の項目に挙がっています（第3節の蒸留）
- **Apple Core AI**: 同じページの関連の項目に挙がっています（端末の上でモデルを動かす仕組み）
- **Open-weight models**: 重みが公開され、自前で動かせるモデル。小型のモデルの多くもこの形で配られています（[解説](open-weight-models.md)）
- **代替: 大きなモデルに一本化する**: 仕事の種類が多く、回数が少ないうちは、1つの大きなモデルで済ませるほうが設計も運用も簡単（筆者の見立て）

## 用語集

| 用語 | 説明 |
|---|---|
| LLM（大規模言語モデル） | 大量の文章で学習し、文章を読んで続きを作り出す AI のモデル |
| パラメータ | モデルの中で、学習によって決まる数値。数が多いほど多くを覚えられるが、動かす費用も大きい |
| 推論 | 学習済みのモデルに入力を与えて、答えを出させる計算。文脈によっては「筋道を立てて考えること」の意味でも使う |
| トークン | LLM が文章を数える単位。料金や、一度に読める量の基準になる |
| 蒸留 | 大きなモデルの出力を手本にして、小さなモデルを学習させる方法 |
| 量子化 | モデルの数値を、より少ないビット数の形に置き換えて、軽く速くする方法。精度が少し落ちることがある |
| エッジ | データセンターではなく、利用者の手元の機器（パソコン・スマートフォン・工場の装置など） |
| ファインチューニング | 学習済みのモデルを、自分たちのデータで追加で学習させて、特定の仕事に合わせること |
| RAG（検索拡張生成） | 質問に関係する文書を検索で探し、それをモデルに渡して答えさせる方法。モデルが覚えていない知識を補える |
| GPU | 大量の計算を並べて行う演算装置。AI のモデルを動かすのによく使う |
| モデルカード | モデルの作り方・用途・限界・ライセンスなどをまとめた説明書 |
| ライセンス | ソフトウェアやモデルを使うときの条件。Apache 2.0 や MIT は、商用でも使いやすい一般的なもの |
