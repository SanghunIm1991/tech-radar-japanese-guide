## 1. 一言でいうと

Open-weight models（オープンウェイトのモデル）は、**LLM（大規模言語モデル）の重み**（学習で決まった、モデルの中身にあたる大量の数値）が公開されていて、誰でも取得して自分の環境で動かせるモデルです。この項目は、そうしたモデルを本番の仕事の選択肢として検討する手法を指しています（Thoughtworks の評価は第7節にまとめます）。

たとえるなら、レストランで料理を注文する（提供元の API を呼ぶ）のではなく、完成したレシピと材料一式を受け取って自分の厨房で作る（自分の環境で動かす）ようなものです。厨房の設備と手間は自分持ちですが、味付けを変えたり、店の外に材料を出さずに済んだりします（筆者の見立て）。

## 2. 解決する課題（なぜ生まれたか）

性能の高い LLM の多くは、提供元のクラウドの API を通してだけ使えます（クローズドなモデル）。この形には、次のような制約があります（筆者の見立て）。

- **データの行き先**: 入力した社内の情報が、提供元のサービスに送られる。業種や国によっては、データを国内や自社の管理下に置く決まり（データ主権）がある
- **提供元への依存**: 料金・利用条件・モデルの提供の終了などを、提供元が決める
- **調整の自由**: 自社のデータでモデルを追加学習（ファインチューニング）させる範囲が、提供元の用意した機能に限られる
- **費用の形**: 使った量に応じて払い続ける。利用が多いと、自前で動かすほうが安くなる場合がある

オープンウェイトのモデルを自分で動かせば、これらを自分で決められます。ただし、その分の運用は自分で背負うことになります。

## 3. 仕組みの概要

**「オープンウェイト」と「オープンソース」の違い**

重みが公開されていても、オープンソースのソフトウェアと同じ意味で「オープン」とは限りません。OSI（Open Source Initiative）のオープンソース AI の定義 1.0 は、AI のシステムを自由に使い・調べ・変え・共有できるために、次の3つを求めています（[OSI: The Open Source AI Definition 1.0](https://opensource.org/ai/open-source-ai-definition)）。

1. **データの情報**: 学習に使ったデータについて、同等のシステムを作れるほど詳しい説明
2. **コード**: 学習と実行に使ったソースコードの全体
3. **パラメーター**: 重みなど

定義は3つすべてを（OSI が認めた条件で）提供するよう求めているので、重みだけを公開したモデルは、この定義を満たしません。「オープンウェイト」は、重みが手に入ることを指す、より狭い言葉です（筆者の見立て）。

**例: Radar が挙げる3つのモデルの系列**（確認日の時点の、各社の Hugging Face のモデルカードによる）

| 系列（開発元） | 確認したモデル | 規模 | ライセンス |
|---|---|---|---|
| DeepSeek（DeepSeek） | DeepSeek-V4-Pro（プレビュー版） | MoE。全体1.6兆、1回に働くのは490億のパラメーター。最大100万トークン | MIT |
| GLM（Z.ai） | GLM-5.3 | 7,530億のパラメーター（モデルカードのメタデータ） | 独自のライセンス（識別子は glm-5.3） |
| Kimi（Moonshot AI） | Kimi-K3.1-Pro | MoE。全体2.8兆、1回に働くのは1,040億のパラメーター。最大約100万トークン。画像も扱う | 独自のライセンス（Kimi K3.1 Pro License） |

出典: [DeepSeek-V4-Pro](https://huggingface.co/deepseek-ai/DeepSeek-V4-Pro)、[GLM-5.3](https://huggingface.co/zai-org/GLM-5.3)、[Kimi-K3.1-Pro](https://huggingface.co/moonshotai/Kimi-K3.1-Pro)

GLM-5.3 と Kimi-K3.1-Pro のモデルカードは、vLLM や SGLang といった推論の道具（モデルを効率よく動かして応答を返すソフトウェア）での動かし方を案内しています。DeepSeek-V4-Pro のモデルカードは、リポジトリの inference フォルダで動かし方を示しています。Kimi-K3.1-Pro は、開発元の API でも使えます（同上）。

**MoE（mixture of experts）とは**

大きなオープンウェイトのモデルに多い作りです。モデルの中に「専門家」（expert）と呼ぶ部品を多数持ち、入力の1つ1つのトークン（文章を細かく区切った単位）ごとに、案内役（router）が一部の専門家だけを選んで計算させます。「専門家」は名前で、分野ごとの専門家とは限らず、実体は同じ形の計算の部品です。全体のパラメーターは多くても、1回の計算に使うのは一部なので、同じ全体の大きさの普通のモデルより速く推論できます。一方で、すべての専門家をメモリーに載せておく必要があるため、GPU のメモリーを多く使います（[Hugging Face: Mixture of Experts Explained](https://huggingface.co/blog/moe)）。

**使い方の形**

1. **自前で動かす**: 自社のサーバーやクラウドの GPU に重みを置き、推論の道具で動かす
2. **クラウドの管理されたサービスで使う**: クラウドの事業者が、オープンウェイトのモデルを API として提供しているものを使う
3. **追加学習してから使う**: 自社のデータで調整してから、1か2で動かす

## 4. アーキテクチャ上の位置づけとトレードオフ

**位置づけ**: AI を組み込むシステムで、「どのモデルを、どこで動かすか」という選択の幅を広げるものです。データベースで、商用の製品とオープンソースの製品を、運用の手間と費用と自由度で比べて選ぶのと同じ構図です（筆者の見立て）。

**得られるもの**

- **データを手元に置ける**: 自前で動かせば、入力が外部に出ない（筆者の見立て）
- **大きさを選べる**: 小さなモデルから非常に大きな MoE のモデルまで、用途に合わせて選べる
- **追加学習**: 重みが手元にあるので、自社のデータで調整できる
- **提供元を替えやすい**: 同じ重みを、自前でも、複数のクラウドでも動かせる（筆者の見立て）

Radar も、同様の点を利点に挙げています（[Radar のページ](https://www.thoughtworks.com/en-us/radar/techniques/open-weight-models)。第7節）。

**代わりに失うもの・注意点**

- **運用の手間と設備**: 大きなモデルは、多くの GPU と、それを動かし続ける技術が要る。MoE は全体を載せるメモリーが要る（第3節）
- **ライセンスの違い**: MIT のように緩いものから、独自のライセンスまである（第3節）。商用利用の条件などを、モデルごとに確かめる必要がある（筆者の見立て）
- **評価の手間**: 公開された性能の数字は開発元の測り方による。自社の仕事で試して比べる必要がある（筆者の見立て）
- **出どころへの配慮**: 開発元の国や組織によっては、社内の規定や取引先の要件で使えない場合がある（筆者の見立て）
- **安全の調整**: 有害な出力を防ぐ仕組みは、自前で動かすなら自分で用意する部分が増える（筆者の見立て）

## 5. 採用を判断するときの観点

- **用途**: まず、データを外に出せない仕事や、大量に繰り返し使う仕事から試す（筆者の見立て）
- **動かす場所**: 自前の GPU か、クラウドの管理されたサービスか。後者は始めやすいが、データの置き場所はそのクラウドの条件による（筆者の見立て）
- **費用**: 自前の場合は、GPU・電力・運用の人手を含めた総額で比べる。利用量が少ないうちは API のほうが安いことが多い（筆者の見立て）
- **ライセンス**: 商用利用・再配布・追加学習したモデルの扱いの条件を、モデルごとに確かめる（筆者の見立て）
- **評価**: 自社の課題で、クローズドなモデルと並べて品質・速さ・費用を測る（筆者の見立て）

## 6. 関連技術・代替技術

- **クローズドなモデルの API**: 運用の手間が最も少ない代替
- **小さな言語モデル（SLM）**: 小さく軽いモデルを用途に絞って使う考え方。オープンウェイトのものも多い（筆者の見立て）
- **GLM**、**Blanket frontier model usage**: Radar のこの項目のページに、関連の項目として載っています
- **推論の道具（vLLM・SGLang など）**: 自前で動かすときの土台（第3節）
- **MoE**: 大きなオープンウェイトのモデルに多い作り（第3節）

## 用語集

| 用語 | 説明 |
|---|---|
| LLM（大規模言語モデル） | 大量の文章で学習し、文章を読んで続きを作り出す AI のモデル |
| 重み（パラメーター） | 学習によって決まる、モデルの中の大量の数値。モデルの「中身」にあたる |
| オープンウェイト | モデルの重みが公開され、取得して自分の環境で動かせること |
| クローズドなモデル | 重みが公開されず、提供元の API を通してだけ使えるモデル |
| オープンソース AI の定義 | OSI が定めた、AI のシステムをオープンソースと呼ぶための条件。重みに加えて、学習のデータの情報とコードの公開も求める |
| ファインチューニング（追加学習） | 学習済みのモデルを、自分のデータでさらに学習させて、用途に合わせること |
| データ主権 | データを、自国や自社の管理と法律のもとに置くという考え方 |
| MoE（mixture of experts） | 多数の「専門家」の部品を持ち、入力ごとに一部だけを使って計算するモデルの作り |
| トークン | LLM が文章を数える単位。1回に読める量も、料金も、トークンの数で表す |
| 推論 | 学習済みのモデルに入力を与えて、出力を得ること |
| GPU | 大量の計算を並行して行うのが得意な演算装置。LLM を動かすのに使う |
| Hugging Face | AI のモデルやデータを公開・共有するためのサービス |
