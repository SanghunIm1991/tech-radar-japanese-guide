Agent sandboxing

名前の手がかり: Agent 代理人 ＋ sandboxing sandbox（子どもが遊ぶ砂場）に入れること

AI エージェントを、外から切り離した囲いの中で、必要最小限の権限だけを与えて動かす手法

たとえるなら

新人に渡すのは、会社の全部の鍵ではなく作業部屋の鍵だけ

外への電話も、決まった相手にしかかけられないようにしておきます。AI エージェント（指示を受けて、自分でツールを使いながら作業を進める AI）が思わぬ動きをしたり、だまされて悪い操作をしたりしても、被害が囲い（サンドボックス）の外に広がらないようにする考え方です。

エージェントに仕事を任せると起きる3つの危険と、サンドボックス化の答え

左が危険、右が答えです。AI が「だまされない」ことは保証できないので、「だまされても大きな被害が出ない環境で動かす」のが共通の考え方です。

だまされる

プロンプトインジェクション（prompt injection）

エージェントが読んだメールや Web ページに悪意ある指示が紛れ込んでいて、それに従ってしまう。

だまされても、届く範囲を狭める

ファイルは作業用のフォルダの外に書けず、ネットワークは許可リストの相手にしか出られない。悪意ある指示に従っても、鍵のファイルを書き換えたり情報を外へ送ったりしにくくなる。下の図で試せます。

思い違いをする

ハルシネーション（hallucination）など

指示を取り違えたり、事実でないことをもっともらしく生成したりして、意図しない操作をする。

壊せるのは囲いの中だけにする

外部のシステムへの権限は必要な分だけに絞る（読み取り専用・下書きまでなど）。削除や送信のように影響の大きい操作は、人が承認してから実行する。

権限が強すぎる

過剰な権限（Excessive Agency）

AI の出力が予想外だったり操作されたりしたときに、損害を生む操作ができてしまうこと。OWASP が LLM アプリケーションの主なリスクに挙げ、原因として、機能が多すぎる・権限が強すぎる・人の確認なしに動ける範囲が広すぎる、の3つを挙げている。

最小権限の原則で、仕事に必要な分だけ

機能・権限・人の確認なしに動ける範囲を絞る。操作してよいかの判断を AI に任せず、操作される側のシステムで確かめる。

試してみる: 囲いの有無で、何が届くかを比べる

「囲いと権限の設定」と「起きたこと」を切り替えると、図と下の説明が変わります。「あり」は、ファイルの書き込みを作業フォルダに限り、鍵のファイルを読ませず、接続先を許可リストに絞った囲い（サンドボックス）に、社内のシステムへの権限の絞り込みと、影響の大きい操作への人の承認（OWASP が勧める、囲いを補う層）を組み合わせた例です。

囲いと権限の設定
起きたこと

囲いの強さには段階がある

OS の機能で1つのプロセスを制限Seatbelt（macOS）・bubblewrap（Linux）など
コンテナDocker など。Linux の名前空間と cgroups で区切る
カーネルを挟む方式gVisor など。アプリの要求がホストのカーネルに直接届かない
軽量な仮想マシンFirecracker など。起動が速く負担の小さいマイクロ VM
弱い・手軽（目安）強い・準備や負担が増えることがある（目安）

一般的な目安としての並べ方です（解説の筆者の整理）。右ほど隔離が強くなる傾向がありますが、どれが強いかは構成によって変わり、特に gVisor とマイクロ VM の比較は意見が分かれます。選び方の一例（筆者の見立て）: 自分の端末で使う開発用のエージェントなら OS の機能やコンテナで足りることが多く、外部の人が入力できる業務用のエージェントなら仮想マシン級の隔離も検討する。

得るもの

  • エージェントが思わぬ動きをしたり、だまされたりしても、被害が囲いの外に広がりにくい
  • 「やってはいけないこと」をプロンプトで言い聞かせるのではなく、仕組みの側で止められる
  • AI がだまされないことを保証できなくても成り立つ

代わりに失うもの

  • 使い勝手: 囲いを厳しくするほど、できることが減る。新しい接続先が要るたびに承認を求められ、待つあいだ作業が止まる
  • 完全ではない: 広く使われるサイト全体への接続を許すと、そこが持ち出し口になりうる。サンドボックスは安全な設計の代わりにならない（gVisor のドキュメントの指摘）
  • 抜け道の管理: 囲いの外で動かす例外を作ると、そこが弱点になる
  • 準備と負担: 強い隔離ほど、環境の用意や動作の負担が増える傾向（筆者の見立て）

実現するための道具の例

推奨でも網羅でもない例です（2026-11-15 の時点）。

sandbox-runtimeOSS（Apache-2.0。研究段階の公開）

コンテナを使わず、OS の機能と通信の中継で、任意のプロセスのファイルとネットワークを制限する。Claude Code のために作られた。

Moby（Docker）OSS（Apache-2.0）

コンテナを作って動かす仕組み。Docker の製品の上流のプロジェクト。

gVisorOSS（Apache-2.0）

アプリケーションとホストの OS のあいだに、強い隔離の層を挟むアプリケーション用のカーネル。

FirecrackerOSS（Apache-2.0）

複数の利用者のサービスを安全に分けて動かすための、軽量な仮想マシン（マイクロ VM）を作る。

E2BOSS（Apache-2.0）／クラウドのサービス

AI が生成したコードを、クラウドの隔離されたサンドボックスで実行する。公式サイトによると、セッションごとに Firecracker のマイクロ VM を割り当てる。

AI エージェント

agent ＝ 代理人

目的を与えられると、ファイルの操作・コマンドの実行・Web の検索などの道具を自分で選んで使いながら、作業を進める AI。

サンドボックス

sandbox ＝ 砂場

中で何をしても外に影響が出ないように、触れられる範囲を制限した実行環境。

最小権限の原則

least privilege ＝ 最も少ない特権

人やプログラムに与える権限を、仕事に必要な最小限にとどめるというセキュリティの基本の考え方。

プロンプトインジェクション

prompt ＝ 促すもの（AI への指示） ／ injection ＝ 注入

AI が読み込む文章に命令を紛れ込ませて、AI に本来の指示と違うことをさせる攻撃。

ハルシネーション

hallucination ＝ 幻覚

AI が事実でない内容を、もっともらしく生成してしまうこと。

OWASP・LLM

OWASP ＝ Open Worldwide Application Security Project ／ LLM ＝ Large Language Model（大規模言語モデル）

OWASP は Web アプリケーションのセキュリティの向上に取り組む非営利の団体。LLM は大量の文章で学習し、文章を理解・生成する AI。

コンテナ

container ＝ 入れ物

アプリケーションと、その動作に必要なものをひとまとめにして、ほかから切り離して動かす仕組み。ホストの OS の中核（カーネル）は共有する。

名前空間・cgroups

namespace ＝ 名前の空間 ／ cgroups ＝ control groups（制御のグループ）

Linux の機能。名前空間はプロセスから見えるものを区切り、cgroups は使える CPU やメモリの量を制限する。

システムコール・カーネル

system call ＝ システムへの呼び出し ／ kernel ＝ 果実の種の中身・核

システムコールは、アプリケーションが OS に「ファイルを開いて」などを頼む呼び出し。カーネルは OS の中核で、ハードウェアや資源を管理する部分。

仮想マシン（VM）

Virtual Machine ＝ 仮想の機械

1台の物理的なコンピュータの上に、ソフトウェアで別のコンピュータを作り出す仕組み。中で動く OS ごと切り離せるので、隔離が強い。

許可リスト

allowlist ＝ 許可の一覧

「これだけは許す」という一覧。載っていないものはすべて拒否する方式。

脅威モデリング

threat ＝ 脅威 ／ modeling ＝ 模型を作ること

システムに対してどんな攻撃や事故がありうるか、どこが弱いかを、設計の段階で整理する作業。
