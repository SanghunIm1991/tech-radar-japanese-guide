Progressive context disclosure

名前の手がかり: Progressive 段階的に進む ＋ Context 文脈・前後の情報 ＋ Disclosure 開示・明かすこと

AI エージェントに、必要な情報を最初から全部渡すのではなく、まず「何があるか」の短い一覧だけを見せ、詳しい中身は必要になったときに読み込ませる手法

たとえるなら

分厚いマニュアルを全部読ませず、目次だけを渡して、「経費精算のときは第5章を」と開いてもらう

新人に、仕事を始める前にマニュアルの全部を読ませるのではなく、目次だけを渡しておき、必要な章をその都度開いてもらうようなものです。AI エージェントでは、目次にあたるのが「名前と説明文の一覧」、章にあたるのが「詳しい手順や資料」です。

エージェントへの情報の渡し方の3つの課題と、この手法の答え

課題と、その答えを対で並べています。LLM（大規模言語モデル）が一度に読める範囲をコンテキストウィンドウ、その中に入れる指示や資料をコンテキストと呼び、量はトークン（文字や単語の断片を数える単位）で数えます。

コンテキストは限りある資源

コンテキストウィンドウ（context window）

上限に収まれば何を入れてもよいわけではない。Anthropic は、トークンが増えるほど、LLM が注意を向けられる量の「予算」が薄まると説明している。

最初は一覧だけ。本文は使うときに読む

最初に載せるのは一覧（スキル1つあたり約100トークンの名前と説明文）だけにし、本文や資料は使うときだけ読み込む（Agent Skills の仕様）。Anthropic は、情報の詰まったトークンをできるだけ少なく選ぶことを、コンテキストの設計の目標に挙げている。下の図で見られます。

入力が長いと、性能が落ちる

コンテキストの劣化（context rot）

Chroma の研究は、18 の LLM で、課題が単純でも入力が長くなるにつれて性能が落ちると報告した。答えに似ているが答えではない文が混ざると、さらに落ちた。

関係のない情報を、最初から入れない

入力が短く保たれる。Thoughtworks は、この手法の効果として context rot の抑制を挙げている。紛らわしい文が混ざる機会も減ると考えられる（筆者の見立て。効果の大きさを測った出典は確かめていない）。

指示が膨らみ、関係のない情報が大半を占める

指示（instructions）

ルール・ツールの説明・手順書を全部最初に渡すと、今の作業に関係のない情報が大半になる。Thoughtworks は2026年4月の版で、「〜せよ」「〜するな」を大量に並べた指示がかえって性能を下げると指摘していた。

手順を分け、詳しい資料へのリンクを置く

手順書やツールの説明を1つの大きな指示にまとめず、スキルや別の資料に分ける。AGENTS.md（エージェント向けの指示ファイル）には詳しい資料へのリンクを置く。Thoughtworks は、作業に合った指示をその場で渡すことで、この弊害を避けられるとしていた（2026年4月の版）。

試してみる: 全部を最初に渡すときと、段階的に開示するときの、コンテキストの中身

5つのスキル（作業の手順をまとめたもの）を持つエージェントに、「リリースノートを書いて」と頼む例です。2本の棒は、それぞれの渡し方でコンテキストに入っている中身です。段階のボタンで、エージェントの立ち上げから資料が必要になるまでを順に進めてください（括弧の中は、詳しい解説の第3節の段階の名前です）。スキルの数・トークンの数は、説明のために作った例です。

依頼の例: 「リリースノートを書いて」（関係があるのは、5つのうち「リリースノートを書く」のスキル）
段階
試す
常に渡す決まり 一覧（名前と説明文） この依頼に関係する本文・資料 この依頼に関係しない本文・資料

数字は説明のための例です（一覧はスキル1つあたり約100トークン、本文は仕様が勧める5,000トークン未満に収めた値にしました）。実際の差は構成によって違うので、減った量は実際の作業で測ります。

スキルのほかにも、いくつかの形がある

Thoughtworks は、この手法は本格的な AI のアプリではほぼ当たり前になったと見ています。上の図はスキルの形（一覧→本文→資料）で、ほかに次の形があります（詳しい解説の第3節）。

ツール定義の後読み

Claude の API では、ツールの定義を最初は載せず、検索して見つけたものだけを読み込める。複数の外部サービスをつなぎ、ツールの定義だけで約55,000トークンを使うことがある構成で、多くの場合85%以上減らせると Anthropic は主張している（開発元の主張）。

必要なときに取りに行く

資料の中身を先に渡す代わりに、ファイルの場所やリンクだけを持たせ、エージェントがその場で取りに行く。Anthropic はこれを「just in time」の取得と呼んでいる。

指示ファイルを短く保つ

AGENTS.md を短く保ち、詳しい資料へのリンクを置く。Thoughtworks が、この手法の例に挙げている。

得るもの

  • 費用と速さ: 毎回送るトークンが減り、料金と応答時間を抑えやすい（Thoughtworks もトークンと費用の削減を挙げている）
  • 精度: 関係のない情報が減り、context rot の影響を受けにくい。Claude のドキュメントは、ツールが30〜50個を超えると正しいツールを選ぶ精度が落ちるとしている

代わりに失うもの・注意点

  • 見落とし: 必要だと気づかなければ読み込まれない（Anthropic の注意）
  • 説明文の書き方に左右される: 一覧の説明文が判断材料のすべて
  • 読み込んだ本文は残る: Claude Code では、一度読み込んだスキルの本文はその後もコンテキストに残り、一覧の説明文も毎回トークンを使う
  • 遅さと手間: その場で探すのは、先に用意したデータを使うより時間がかかる
  • 何でも後読みにはしない: Claude のドキュメントは、ツールが10個未満なら tool search を使わないほうがよく、よく使う3〜5個は最初から載せておくよう勧めている

導入するときに決める5つのこと

Thoughtworks はこの手法を Adopt に置いています。使うかどうかより、どこまで後読みにし、どう確かめるかが要点です（筆者の見立て）。

分けるほどの量か？

全部を渡しても短いなら、無理に分けなくてよい。指示が膨らんできたら分ける（筆者の見立て）。

何を最初から渡すか？

安全のための決まりなど、どの作業でも守らせたいものは最初から渡し、特定の作業でしか使わない手順を後読みにする。Anthropic も、最初に読み込む情報と、その場で探す情報の組み合わせを勧めている。

説明文で呼ばれるか？

「いつ使うか」が分かるように書き、呼ばれるべき場面で呼ばれているかを確かめる。

費用をどう測るか？

Claude の tool search の場合、後読みで読み込まれた分も、通常の入力トークンとして数えられる。後読みにしたツールの定義も、リクエストには毎回すべて含めて送る（コンテキストに載るのは見つかったものだけ）。減った量は実際の作業で測る。

使うエージェントは対応しているか？

Agent Skills や AGENTS.md は公開の形式だが、どこまで対応しているかはツールによって違いうる（筆者の見立て）。

用語（タップで開く）

下線の付いた等幅の字は元の語（英単語・略語・名前の元になった語）で、＝のあとがその意味、または略語の元の綴りです。覚えるための手がかりにしてください。

LLM（大規模言語モデル）

LLM ＝ Large Language Model（大規模な言語のモデル）

大量の文章で学習し、文章を読んで続きを作り出す AI のモデル。

AI エージェント

agent ＝ 代わりに行動する者・代理人

指示を受けて、ファイルの読み書きやコマンドの実行などのツールを自分で使いながら、作業を何段階も進める AI の仕組み。

コンテキスト

context ＝ 文脈・前後の状況

LLM に一度に渡す、指示・会話・資料などの情報の全体。

コンテキストウィンドウ

context ＝ 文脈 ／ window ＝ 窓

LLM が一度に読める量の上限。トークンの数で表す。

トークン

token ＝ しるし・引換券

LLM が文章を数える単位。おおよそ単語や文字の断片にあたる。多くのサービスの料金はトークンの数で決まる。

context rot

context ＝ 文脈 ／ rot ＝ 腐ること・劣化

入力が長くなるにつれて、LLM の正確さが落ちていく現象。

context engineering

context ＝ 文脈 ／ engineering ＝ 設計して作り上げること

LLM に何を、いつ、どれだけ見せるかを設計すること。この手法はその基本の手法の1つ。

Agent Skills

agent ＝ 代理人 ／ skill ＝ 技能

作業の手順・スクリプト・資料を1つのフォルダにまとめ、エージェントが必要なときに読み込めるようにする形式。中心に SKILL.md を置く。

AGENTS.md

agents ＝ エージェントたち ／ .md ＝ Markdown のファイルの拡張子

コーディングエージェント向けに、ビルドやテストの手順、コードの書き方の決まりなどを書いておく Markdown のファイル。

MCP

MCP ＝ Model Context Protocol（モデルにコンテキストを渡すための約束事）

AI のアプリと外部のツールやデータをつなぐための共通の約束事（プロトコル）。

RAG（検索拡張生成）

RAG ＝ Retrieval-Augmented Generation（検索で補強した生成）

質問に関係のある文書を検索し、その部分を LLM に渡して答えさせる手法。

ツール定義

tool ＝ 道具 ／ definition ＝ 定義

エージェントが使えるツールの名前・説明・受け取る値を書いたもの。これもトークンを使う。
