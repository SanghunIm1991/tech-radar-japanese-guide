## 1. 一言でいうと

Stateful guardrails は、LLM（大規模言語モデル）を使った対話の仕組みを守る**ガードレール**（危険な入力や出力を見つけて止める安全の仕組み）を、1つのメッセージごとではなく、**会話の流れ全体**を見て働かせる手法です。「ステートフル」は「状態を持つ」という意味で、直近のやりとりの履歴や、その会話でこれまでに出た警告の回数などを覚えておき、判断に使います（[Radar のページ](https://www.thoughtworks.com/en-us/radar/techniques/stateful-guardrails)の定義による）。

たとえるなら、店の入口で客の手荷物を1回ずつ調べるだけでなく、同じ客が何度も来て、少しずつ部品を持ち出していないかまで見る警備のようなものです（筆者の見立て）。

## 2. 解決する課題（なぜ生まれたか）

従来のガードレールは、利用者の今回の入力か、モデルの今回の出力だけを、その場で調べるものが中心でした（[arXiv:2607.19361](https://arxiv.org/abs/2607.19361) の要旨）。このやり方では、**1つ1つは無害に見えるメッセージを積み重ねて、最後に危険な答えを引き出す**攻撃を見逃しえます。

その代表例が、Microsoft の研究者らが報告した Crescendo という脱獄（ジェイルブレイク）の攻撃です。一般的な質問から始め、モデルの答えを引用しながら少しずつ際どい方向へ話を進めて、最後に本来は断られる内容を引き出します。各ターン（1往復のやりとり）は一見無害なのが特徴で、要旨によると、さまざまな商用・公開のモデルで高い成功率を示しました（[arXiv:2404.01833](https://arxiv.org/abs/2404.01833)。USENIX Security 2025 に採録）。

Stateful guardrails の論文は、こうした会話をまたいで積み上がる危険を「会話のリスクの蓄積（Conversational Risk Accumulation、CRA）」と呼び、要旨では次の3つの型を挙げています（[arXiv:2607.19361](https://arxiv.org/abs/2607.19361) の要旨。本文の表では、さらに細かく5つの型に整理しています）。

- **意図が少しずつずれていく**: 最初は普通の目的だったのが、だんだん危険な方向へ変わる
- **禁止された指示を断片に分けて組み立てる**: 1回では断られる依頼を、部品に分けて集める
- **機微な情報が少しずつ集まる**: 機微な情報を何度にも分けて少しずつ聞き出し、積み上げる

## 3. 仕組みの概要

**Radar が説明する形**（[Radar のページ](https://www.thoughtworks.com/en-us/radar/techniques/stateful-guardrails)）

- 直近のターンの履歴を要約したものを、ポリシー（何を許し、何を禁じるかの決まり）ごとの検査にかける
- 会話（セッション）ごとに、警告（strike）や利用の禁止（ban）の状態を保つ
- エージェントが動く前の関門として実行時に働き、従来の1ターンずつの入力・出力の検査と**併用**する

**動きの例**（筆者の整理）

1. 利用者が新しいメッセージを送る
2. 従来の検査で、そのメッセージだけを調べる
3. 直近の数ターンの要約とあわせて、会話全体の検査にかける
4. 危険の兆しがあれば、その会話の警告の回数を1つ増やし、確認を求める・答えを控えめにするなどの対応をとる
5. 警告が決めた回数に達したら、その会話を止める
6. 問題が無ければ、エージェントやモデルに処理を渡す

**論文の形**（[arXiv:2607.19361](https://arxiv.org/abs/2607.19361) の要旨）

論文は、会話の層で働く仕組みとして、3つの「軌跡」の信号を追う方法を提案しています。

1. 会話の最初に示された意図から、話がどれだけ離れたか（意味のずれ）
2. 会話で出てきた人物や組織などについて、どれだけ機微な情報が集まったか（情報の蓄積のグラフ）
3. モデルがだんだん要求に応じやすくなっていないか

これらを組み合わせて会話全体の危険度を点数にします。評価用に、危険な会話と、話題をそろえた無害な会話を含むデータセット（CRA-Bench）も公開しています。

**論文の結果の読み方**

論文の本文によると、人が書いた会話のデータ（段階的に危険へ進む会話750件と、長さをそろえた無害な会話222件の計972件）で、合成データだけで学習した論文の小さなモデルは AUROC（見分ける力の指標で、1.0 が完全、0.5 が当てずっぽう）が 0.919 でした。同じデータで、既存の安全判定モデルの Llama Guard 3 は 0.695、Qwen3Guard は 0.997 で、論文自身も Qwen3Guard を上限の目安、自分たちの方法を実用上の中間の選択肢と位置づけています（[arXiv HTML 版 第1節・第2.2節](https://arxiv.org/html/2607.19361v1)）。つまり「状態を持てば必ず強くなる」ではなく、どの判定器を使うかも大事だということです（筆者の見立て）。

**記録と監視**

ガードレールの判定は、あとから見直せるように記録しておくのが大切です。Radar のページは、本番での利用で判定を Langfuse（LLM のアプリの記録と評価の道具）で追ったと述べています。Langfuse のドキュメントは、ガードレールの各段階をトレース（処理の流れの記録）として残し、点数（スコア）を付けて時系列で追ったり、一部を人が確かめて判定の正しさを評価したりする方法を説明しています（[Langfuse: Security & Guardrails](https://langfuse.com/docs/security-and-guardrails)）。

## 4. アーキテクチャ上の位置づけとトレードオフ

**位置づけ**: LLM のアプリの「安全の層」の設計です。ネットワークの防御で、1つの通信だけを見るファイアウォールに加えて、通信の流れ全体から不審な動きを見つける仕組みを置くのと似ています（筆者の見立て）。

NVIDIA の NeMo Guardrails は、入力・検索結果・会話の流れ（dialog rails）・ツールの実行・出力のそれぞれで働くレールを用意しており、会話の流れを扱う層を持つ既存の道具の例です（[NeMo Guardrails: Rail types](https://docs.nvidia.com/nemo/guardrails/latest/about-nemo-guardrails-library/rail-types)）。

**得られるもの**

- **段階的な攻撃への備え**: 1回ずつの検査では見えない、積み上げ型の攻撃を見つけやすくなる（論文の要旨）
- **状態に応じた対応**: 警告を重ねた利用者を止めるなど、会話ごとに対応を変えられる（Radar のページ）

**代わりに失うもの・注意点**

- **遅延と費用**: 毎ターン履歴を評価するので、応答が遅くなり、判定のための LLM の呼び出しの費用もかかる（Radar のページ）
- **誤って締め出す**: 警告や禁止の境目を調整しないと、正当な利用者を止めてしまう（Radar のページ）
- **状態の保管**: 会話の履歴や警告の回数をどこに、どれだけの期間保つかの設計が要る。履歴には個人情報が入りうるので、保管と削除の決まりも要る（筆者の見立て）
- **研究の段階**: 論文の結果は主に合成のデータセットでのもので、別の種類の攻撃への効き目は今後の課題とされている（[arXiv HTML 版 第13節](https://arxiv.org/html/2607.19361v1)。筆者の要約）

## 5. 採用を判断するときの観点

- **対象**: 複数のターンにわたって対話する仕組みか。1回の質問に答えるだけなら、従来の検査で足りることが多い（筆者の見立て。複数ターンの本番の仕組みに試すよう勧める点は Radar のページも同様）
- **扱う情報の重さ**: 個人情報や危険な知識を扱いうるか。重いほど、会話全体を見る価値が上がる（筆者の見立て）
- **既存の検査を残す**: 1ターンずつの入力・出力の検査は外さず、上に重ねる（Radar のページ）
- **境目の調整**: 本番の記録を使って、誤って止めた件数（偽陽性）と見逃した件数を測り、境目を調整する（筆者の見立て）
- **応答の速さの余裕**: 判定を同期で行うか、裏で非同期に行って次のターンから効かせるかを、遅延の許容度で決める（筆者の見立て）
- **記録**: 判定の結果を、あとから見直せる形で残す（第3節の Langfuse の例）
- **費用の見積もり**: 判定に LLM を使うなら、1ターンごとの判定の呼び出しが、本来の応答の呼び出しに上乗せされる。小さな判定用のモデルで足りるかを試す（筆者の見立て）

## 6. 関連技術・代替技術

- **LLM guardrails**、**Langfuse**: [Radar の Stateful guardrails のページ](https://www.thoughtworks.com/en-us/radar/techniques/stateful-guardrails)の関連の項目に挙がっています
- **NeMo Guardrails**: 会話の流れを扱うレールを持つ、NVIDIA のガードレールの道具（第4節）
- **代替: 会話の長さや回数の制限**: 1つの会話のターン数を絞る、一定の回数で会話をリセットするなど、簡単な方法でも積み上げ型の攻撃を難しくできる（筆者の見立て）

## 用語集

| 用語 | 説明 |
|---|---|
| LLM（大規模言語モデル） | 大量の文章で学習し、文章を読んで続きを作り出す AI のモデル |
| ガードレール | LLM への危険な入力や、LLM からの不適切な出力を見つけて、止めたり書き換えたりする安全の仕組み |
| ステートフル | 前のやりとりの情報（状態）を覚えておき、次の判断に使うこと。反対はステートレス |
| ターン | 対話の中の1往復のやりとり |
| セッション | 1つの会話のまとまり。始まりから終わりまでの一連のターン |
| ポリシー | 何を許し、何を禁じるかの決まり |
| 脱獄（ジェイルブレイク） | 工夫した入力で、モデルの安全の制限をすり抜け、本来は断られる答えを引き出すこと |
| AUROC | 2つの種類（危険・無害など）を見分ける力の指標。1.0 が完全で、0.5 は当てずっぽうと同じ |
| トレース | 1回の処理の流れ（どの段階で何を受け取り、何を返したか）の記録 |
| 偽陽性 | 問題の無いものを、問題ありと誤って判定すること |
| エージェント | 指示を受けて、ツールを自分で使いながら作業を何段階も進める AI の仕組み |
